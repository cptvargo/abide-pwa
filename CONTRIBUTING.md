# Contributing to ABIDE PWA

Thank you for your interest in contributing to the ABIDE Bible App.  
This project is a proprietary work created by **Jesus Vargas**, and contributions are accepted **by invitation only**.

Even with limited external contribution, this guide outlines how development is structured and how collaborators should participate.

---

## 🌿 Vision

ABIDE aims to deliver a clean, insightful, offline-first Scripture experience with:

- A custom translation (VSV)
- A Hebrew and Greek lexical engine
- Verse-level theological insights
- A seamless PWA experience
- Beautiful, distraction-free UI

All contributions must preserve this vision.

---

## 🛠 Development Workflow

### **Branches**

- `main` → Production-ready, stable code
- `dev` → Active development branch
- `feature/*` → One branch per feature or improvement  
   Example:
  feature/longpress-improvements
  feature/genesis-insights-2
  feature/highlighting-system
  feature/ui-cleanup

## Commit Message Guidelines

Use **conventional commit messages**:

feat: add verse highlighting system
fix: resolve iOS text-selection conflict
refactor: optimize scroll handler and long-press detection
docs: update README with installation steps
chore: bump dependencies
style: adjust verse typography spacing|

This keeps commit history readable and easy to search.

---

# 🔀 Pull Request Guidelines

All PRs must:

- Target the **dev** branch
- Contain a clear, descriptive title
- Explain what the PR changes and why
- Reference related features or issues
- Not introduce breaking changes unless approved
- Pass build steps (`npm run build`)
- Follow React + Tailwind coding standards

Example PR titles:

[Feature] Add Hebrew Lexicon Loader
[Fix] Improve PWA Offline Cache Behavior
[Refactor] Consolidate Insight Loading Logic
[Docs] Add Contributing Guide

---

# 🧩 Coding Standards

## React + Vite

- Use **functional components** only
- Use React Hooks (`useState`, `useEffect`, `useRef`, etc.)
- Keep components **small, focused, and readable**
- Place visual components in `/src/components`
- Place data/logic helpers in `/src/lib`
- Keep business logic out of components when possible

## TailwindCSS Styling

- Prefer semantic, logical groupings of class names
- Avoid excessive inline styling
- Use consistent spacing, typography, and color patterns
- Mobile-first design is required

# 📘 Data Standards (Bible, Insights, Lexicon)

ABIDE uses a structured JSON-based data system.

### Insight JSON Format (Required)

{
"1": {
"insight": "Theological explanation for verse 1...",
"hebrew": {
"word": "bereshit",
"meaning": "in the beginning"
}
},
"2": {
"insight": "Explanation for verse 2...",
"hebrew": { ... }
}
}

### Scripture Loading

Uses:

loadChapter(book, chapter, "vsv")

### Notes Storage

All notes must follow this key format:

note-{book}-{chapter}-{verse}

This maintains consistency across all devices and features.

---

# 🧠 Theological Integrity Requirements

Because ABIDE handles Scripture, translation, and commentary:

### Contributors must ensure:

- Doctrinal clarity
- Hebrew and Greek accuracy
- Consistency with ABIDE's tone (pastoral, accessible, faithful)
- No denominational bias or divisive commentary
- No speculative doctrine or commentary outside source text

### AI-generated content must be reviewed

Insight drafts generated by AI must be theologically evaluated before being merged.

---

# 🧪 Testing Requirements

Before submitting changes:

### Test on **mobile**:

- iPhone (Safari)
- Android (Chrome)

### Test on **desktop**:

- Chrome
- Edge
- Safari (if available)

### Verify that:

- Long-press works reliably
- No accidental iOS text selection occurs
- Scrolling is smooth and unaffected
- PWA offline mode loads correctly
- Layout stays consistent at all breakpoints
- Notes load/save correctly
